# Agent profiles — autocut

证据：本会话观察到的需求方环境（2026-10-28：Claude Code 2.1.303、Opus 5.5、bypass permissions、全局 CLAUDE.md、约 60 个 skill 和上百个延迟加载的 MCP 工具）+ baseline 实测（`baseline-observations.md`，进行中）· 假设标 [A] · 日期：2026-10-28

## P1 — Opus-in-Claude-Code（主画像）

| 维度 | 值 |
|---|---|
| 模型 | Opus 5.5（需求方日常使用的模型） |
| Harness | Claude Code CLI，交互式会话；工具有 Bash、Read、Write、Edit、Skill、Agent 等 |
| 输出限制与渲染 | Bash 输出过长会被截断（约 30k 字符），终端渲染 Markdown；ffmpeg 默认的 stderr 横幅和进度很容易占满上下文 [A，baseline 验证中] |
| 调用时的上下文 | 会话中段，前面可能已经有大量对话；空余预算大约 50–150k token [A] |
| 竞争工具 | 约 60 个 skill，外加 Gmail/Docs/Chrome 等上百个 MCP 工具（延迟加载）；与剪辑相关的竞争者是"直接写 ffmpeg 命令"和"写 Python 脚本" |
| 权限与自主度 | bypassPermissions，基本不弹确认；全局规则要求删除走 `trash`、不覆盖未备份文件、计费网络下不下载大文件 |
| 知识 | 熟悉 ffmpeg/ffprobe 的常用参数，但对 filter_complex 细节、关键帧对齐、VFR 等容易犯错 [A，baseline 验证中]；不了解 autocut（全新接口） |
| 语言 | 委托人用中文；输出可中可英 |

**必须完成的任务**（委托人原话风格）
- "把这条口播的长停顿剪掉，别剪太碎"
- "这条录像里我说错重来的地方和口头禅都删掉"
- "OBS 录的游戏实况，把没说话又没看点的段落剪掉"
- "直播录像切 3 条高光发抖音，竖屏带字幕"
- "用这几段素材和这首 BGM 做个卡点混剪"
- "按这个文稿做个知识视频，要配音、字幕、配图"
- "拿这句台词做个鬼畜"
- "先别渲染，导出成 Final Cut / 达芬奇工程我自己微调"
- "这条能不能火？哪里要改？"

**委托人**：开发者型创作者。希望一句话交代清楚，不想被问 30 个确认问题；但一定要能看到剪掉了什么、为什么剪（信任问题）。只在发布前看最终结果和摘要。

## P2 — Haiku-subagent（最弱也必须能过的画像）

| 维度 | 值 |
|---|---|
| 模型 | Haiku 5.5 |
| Harness | 两种情况：被主 agent 派出去的 subagent（没有对话历史，只有一段任务说明）；或者为了省钱，用 Haiku 跑的批处理 |
| 上下文 | 预算更小、注意力更弱；工具描述要更直白 [A] |
| 知识 | ffmpeg 参数更容易记错；更可能"声称完成"却没有验证 [A，baseline 验证中] |

设计含义：接口的成功标准以 P2 为下限，因为它的位置相当于可访问性要求。P2 能通过，说明接口本身足够清楚。

## P3 — 无人值守的切片流水线（特殊约束画像）[A]

| 维度 | 值 |
|---|---|
| 模型 | Sonnet/Haiku |
| Harness | `claude -p` 在脚本里运行（例如每次直播结束后跑一次），中途没有人确认 |
| 特殊约束 | 不能有交互式提问；所有决定都要落盘留痕，供委托人第二天审阅；失败必须明确报告，不能"静默降级" |

## 不在设计目标内
- 没有 shell 的纯聊天 connector（claude.ai 网页）：视频文件在本地，不在它的处理范围内。
- 云端批量渲染农场。
