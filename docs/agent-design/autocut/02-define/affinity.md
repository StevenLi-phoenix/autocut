## 读法

- **用标签代替便签颜色**，标签同时写明 profile 和 runset：
  - `h1` / `o1`：haiku / opus，批 1 隔离版（`baseline-2026-10-28-iso`，T1–T4）
  - `h2` / `o2`：haiku / opus，批 2（`baseline2-2026-10-28`，T5–T9）
  - `hu` / `ou`：haiku / opus，未隔离的批 1（`baseline-2026-10-28`）
  - `x`：作废、污染或被打断的运行（`aborted-*`、`contaminated/`、`interrupted/`）
- **计数口径**：比例只在固定任务集上算，即隔离版 36 个 case（每个 profile 18 个，每个 task×model 2 次）。未隔离的数据单独标出，不和隔离版相加。每个格子只有 n=2，所以比例只说明"出现过、出现得多不多"，不能当作稳定的失败率。
- 卡片从 agent 的视角写：它相信了什么，看到了什么。括号里是我的旁注。agent 在 debrief 里提的改进想法标为 **(suggestion)**，只当假设。每条 suggestion 都已经追到它背后的需要，没有单独成簇。
- 推测标为 `[assumption — validate by …]`。

## 板顶：一句话问题

在 Claude Code 里收到一句中文剪辑委托后，agent（P1 Opus 和 P2 Haiku）手里只有 ffmpeg 的原始输出和自己在机器上搜到的模型。它用这些推断素材内容，又用同一套推断确认成品，最后把决定留在 `/tmp` 里和最终回复的文字里。需要语义判断的任务（重说、高光、对拍），haiku 失败一半；opus 每个 case 要花 $1.5–2.4、8–15 分钟。所有 case 都把"听一遍""导入剪辑软件试试"留给了委托人。

## 只读簇头（准入检查：只读这一节，就该知道 agent 为什么失败）

**SH-A 感知：agent 看不见也听不见素材，只能从原始信号里自己拼出"发生了什么"。怎么拼，取决于手边碰巧有什么**
- A-1 机器上没有一个能被发现的来源，告诉 agent"谁在什么时候说了什么"。agent 只好扫盘、借别的项目的环境、现写 Swift，能力随运气变化
- A-2 拿到的时间戳和检测结果都不带可信度。haiku 照单全收，并据此下刀；opus 花调用自己做交叉验证
- A-3 委托里的主观词（长停顿、无聊、精彩、高光）都没有可操作的判据。agent 拿最好读的那一路信号和凭经验定的阈值当答案，即使反证已经在上下文里
- A-4 素材的结构没有任何声明。轨道角色、拍网格、画面内容全靠从波形和抽帧倒推；推断写进结论以后，就不再标明是推断

**SH-B 验证：agent 没有一个独立于生成过程的办法确认成品符合意图，于是用算得出来的代理量宣布成功**
- B-1 复核和生成用的是同一双"眼睛"：重跑同一个检测器，用同一个 ASR 重转写。生成时看不见的地方，复核时照样看不见
- B-2 目标属性没有可测的定义。agent 把"字落在拍上"换成"切片长度能被拍长整除"，把"音画同步"换成"两条流一样长"。代理量必然成立，目标却没有达成
- B-3 下游能不能接受，无从检验。工程文件格式是凭记忆写的；"能导入"先被写成事实，后文才补一句"没打开过"

**SH-C 反馈：底层工具的沉默、短报错和长流水都不是写给 agent 看的，每一种都逼它去猜**
- C-1 空输出至少有四种含义：没检出、阈值不对、命令写错、错误被自己吞掉。agent 分不清，于是随便选一个解释、绕开，或者白跑一轮
- C-2 报错只说"不认识"，不说"现在该怎么写"。ffmpeg 9 改了名的选项、zsh 的分词和数组语法，每撞上一次就耗一轮
- C-3 工具只吐逐窗口、逐帧的流水，没有面向决策的摘要。"太长"的真实代价是噪声盖住了异常，还要多跑一轮去筛，而不是上下文溢出
- C-4 shell 拼装让失败看起来像成功：`|| echo 通过`、`2>/dev/null`，还有 grep 没匹配时的退出码
- C-5 长而不透明的路径只能手抄，抄错一个字符，一整批命令就白跑；路径里的词还被当成线索，让 agent 去找根本不存在的东西

**SH-D 状态：剪辑决定、文件来历和后台进程，agent 和委托人都看不到记录**
- D-1 剪辑决定只存在于 `/tmp` 下的脚本和最终回复的文字里，交付物旁边什么都没留；第二天没法复核"剪了什么、为什么剪"
- D-2 共享空间里的文件没有来历：固定名字的 `/tmp` 目录互相覆盖、突然消失；素材旁边的隐藏缓存被半信半疑地用掉
- D-3 长命令转入后台以后，agent 手里没有属于自己的句柄；取消只能按命令行片段 `pkill`，会波及哪些进程，agent 看不见

**SH-E 契约与边界：任务要求和资源边界只用自然语言给出，agent 按字面硬凑，按习惯补空**
- E-1 字面要求和素材或意图冲突时（"3 个高光"、"15 秒"、"输出 X"），agent 按字面交付，把冲突写成脚注，交出一个自己都不信的结果
- E-2 约束只说了"不许下载、不许安装"，没说"可以用什么"。agent 把"本机已有"当成"可以用"，于是读了别的项目、仓库里的模型和隐藏缓存
- E-3 视频剪辑没有现成的"做完"标准，agent 拿全局软件工程规则（venv、单测、logging）填空；opus 多花的调用和钱有一部分花在这里
