# Problem statement v1 — 视频创作者的剪辑过程

证据等级：**traces + requester** · 日期：2026-10-28 · 版本 1（根据亲和图修订 v0）
依据：`affinity-diagram.md`（SH-1 至 SH-7）、`../00-requester-account.md`（R1–R5）

## Who
**主要用户**：个人或小团队创作者，把录下的素材（口播、录课、游戏录屏、直播录像、音乐和画面素材、文稿）做成一种或多种可发布的作品：知识/讲解、游戏实况、直播切片、混剪、鬼畜。他们中有人会把操作交给 AI agent 代劳（R1）。
**其他利益相关者**：
- 观众：他们的留存决定作品表现（SH-6）
- 在剪辑软件里接手的人：可能是创作者自己，也可能是剪辑师（SH-3）
- 被切片的主播、被鬼畜的人、音乐和影视版权方（H1）
- 代劳的 agent 和为它付费的人（见 `docs/agent-design/autocut/`）

## What
- **现状**：每种类型都有大量机械性判断：删掉重说的 take、去掉死寂、逐句打字幕、对拍和拼字、在几小时直播里找高光、把文稿对上配音和画面（SH-5）。现有自动化工具的结果，要么是按阈值剪的，会伤到字和节奏，也会漏掉没人说话的高光（A1–A3）；要么是一键生成、改不动的成片（B4）。工具不说明为什么这样剪（B3），参数效果要跑完整条才看得到（B2）。所以创作者逐条复查（B1），再把结果搬进剪辑软件，交接时又常常坏掉（C2）。手机素材、可变帧率、多音轨、长素材让这些问题更严重（SH-4）。
- **期望状态**：机械性判断能很快做出来，而且每一个判断都能被创作者看懂、复核、单独改掉，不必推倒重来；改完的结果能完整交给下一站（工程文件、字幕、多种画幅）。成片在创作者认为影响留存的地方站得住：开头、死寂、节奏、字幕、画幅。
- **未满足的需求**：快速、有把握地知道机器的哪些决定是对的；用最小的代价改掉错的那几个；发布前能判断这条视频会在哪里流失观众。

## When / Where
- 录完的当天，在自己电脑上，开剪之前或刚开剪的时候
- 下播后的几个小时内：切片有时效窗口（S59、S60、S62）
- 发布前最后一遍检查：开头、字幕、画幅
- 素材经常不规整：手机竖屏、可变帧率录屏、OBS 多音轨、2–4 小时的直播（SH-4）

## Why it matters
- **时间**：手剪死寂要"几个小时"，自动化能压到"几分钟"（S05）；一条 2 分钟讲解视频要做几个小时（S72）；鬼畜"光拼字就要 30 小时以上"，一个视频要做几个月（S78）；切片错过时效就没量（S59）。
- **自动化被放弃**：修正成本一旦超过省下的时间，创作者就退回手剪（S68），或者不敢用"全部移除"（S03）。现在的局面是：不管工具多快，审阅和修正的成本都由人来承担。
- **观众**：死寂会让人以为视频结束了，过度剪辑会让人疲劳（S88、S27）；字幕剪完不同步，听障观众和静音观看的人就看不懂（C3）。需求方把成功定义为"爆款"（R5），也就是观众侧的结果。
- **代价不止时间**：按积分或时长收费、上传素材的隐私顾虑、国内装不上下不动（SH-7）。

## Why this medium
- 素材在本地，而且很大（几 GB、几小时）。上传云端又慢又贵，还有隐私顾虑（S29、G2），所以处理在本机完成。
- 需求方和一部分用户通过 AI agent 工作（R1），因此同一份"剪辑决定"要能让 agent 读写，也要能让人在可视化界面里复核。
- 下一站常常是专业剪辑软件（C1），所以要能导出它们认的工程格式，而不是只出一个 mp4。

## What we know / still need to learn
- 已知：见亲和图 SH-1 至 SH-7，各条都标了来源。
- 未知 → 研究问题：
  1. 中文平台（B站、抖音）上的创作者在剪辑上的第一手说法：traces 没能抓到 → 访谈指南主题 A–D，每种类型访谈 2–3 人
  2. 鬼畜和混剪创作者对"自动初稿"的接受度：证据只有 S68、S70、S78 → 访谈主题 D，外加原型测试
  3. 爆款的剪辑杠杆到底有多大：现有证据只有官方读图方法和经验帖 → 现场研究（同一位创作者用和不用工具，各发 N 条，比较前 30 秒留存和平均观看时长）
  4. 用户在审阅时最常改的是哪一类决定 → 可用性测试时记录
