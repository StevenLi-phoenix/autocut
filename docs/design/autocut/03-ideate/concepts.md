# Ideate — 头脑风暴与概念选择

日期：2026-10-28 · 依据：`../02-define/problem-statement.md`、`personas.md`、`storyboards.md`、`../01-empathize/reference-remotion.md`

## 1. How might we…（从问题陈述和 persona 痛点推导）

1. 怎样让创作者**几秒钟内**核对机器的每个决定，而不用重新渲染整条？（B1、B2 · 阿哲、周老师）
2. 怎样让每个决定都能**单独撤销或调整**，不用推倒重来？（B4 · 全部）
3. 怎样在**没人说话**的时候也判断出值不值得留？（A3 · 小鹿、阿哲的游戏实况）
4. 怎样让剪口始终落在**完整的字、完整的意思**上？（A2）
5. 怎样让**人和 agent 改同一份东西**？（R1 · 阿哲）
6. 怎样把粗剪**完整交给剪辑软件**，字幕也一起跟过去？（C1–C3 · 阿哲、Kiko）
7. 怎样在发布前告诉创作者**观众会在哪里流失**？（F1、F2 · 阿哲、小鹿）
8. 怎样把对拍、拼字、找高光这些体力活变成**可以接着改的材料**？（E2、E3 · Kiko、小鹿）
9. 怎样让不规整的素材不再导致工具**静默失败**？（D1–D4、B3）

## 2. 发散（第一轮，不评判，记数量）

1. 决定清单：每一刀一行，写明剪/留、理由、把握度
2. 文字稿为主的审阅页：被剪的句子画删除线，旁边写理由
3. "按方案播放"：播放器跳过被剪的区间，不渲染也能预览
4. 波形 + 剪切区 + 可拖动的边界
5. 把握度分级：确定的直接通过，拿不准的标黄进审阅队列
6. 键盘审阅：J/K 跳到下一个拿不准的决定，空格播放，X 切换剪/留
7. 剪口吸附：词边界（ASR）→ 能量最低点 → 10ms 淡入淡出
8. 节奏档位：紧凑 / 自然 / 从容，对应保留多长的停顿（A4）
9. 保护区间：标出一段，任何配方都不动（S24）
10. 重说检测：相邻句子相似 + "不对 / 重新说 / sorry" 之类标记 → 保留最后一遍
11. 无语音高光：游戏音轨爆发 + 画面剧烈变化 + 弹幕爆发
12. 多音轨感知：用人声轨做判断，用混音轨输出
13. 一份方案文件作为唯一事实来源，CLI、agent、审阅页都读写它
14. 导出 FCPXML / EDL / SRT / 剪辑软件标记 / 音节片段库
15. 发布前体检：开头多久进入正题、死寂、节奏、字幕、响度、画幅 → 一条"流失风险时间线"
16. 爆款分：只用来给候选排序
17. 竖屏裁切：跟着画面主体走的平滑裁切框
18. 一键成片模板（黑盒，作为对照）
19. agent 写 Remotion 代码生成视频
20. 素材预检：先报告可变帧率、旋转、奇怪帧率、多音轨，再分析
21. 鬼畜材料包：音节切片 + 节拍网格 + 第一版对拍
22. 混剪镜头库：切镜头 + 每个镜头的运动/亮度描述 → 按拍组装
23. 知识视频：文稿 → 本机 TTS → 逐句字幕 → 按句分配配图 → 缓慢推拉
24. 直播候选清单：带理由，开头结尾吸附到句子边界
25. 方案版本历史：每次改动都留一版，可回退
26. 只出标记、不剪片的"剪辑软件助手"模式
27. 切片输出里附上授权提醒（H1）
28. 留存曲线预测器（太玄，记录但不追）

## 3. 收敛：四个真正不同的概念

### 概念 A「方案即文档」（修订模式）
每个配方（去停顿、去重说、高光、卡点、鬼畜材料、知识视频）都只做一件事：**写出一份声明式方案**，也就是时间线 JSON。方案里每一刀都带理由和把握度。人通过本地审阅页复核：文字稿加时间线，"按方案播放"即时预览，单个决定可以切换、拖动或保护。agent 通过 CLI 读写同一份方案。确认后用 ffmpeg 出片，或导出剪辑软件工程，或做发布前体检。
**隐喻**：文档的"修订模式"。机器像合作者一样提出修改建议，作者逐条接受或拒绝。这对应 B5（像改文档一样剪）和 B1（逐条过目）。
覆盖想法：1–16、20–27

### 概念 B「视频即代码」（Remotion 路线）
agent 为每个视频写一段 React composition，在 Studio 里预览，用无头 Chrome 渲染。
覆盖想法：19、23

### 概念 C「一键成片 + 爆款分」
上传素材，直接拿到若干条成片，按分数排序，挑一条发。
覆盖想法：16、17、18

### 概念 D「只给标记」（剪辑软件助手）
永远不出片，只把分析结果（切点、节拍、高光、重说）作为标记和子片段导出到剪辑软件。
覆盖想法：14、21、26

## 4. 评估：先看对 persona 和问题的契合度，再看可行性

| 判据 | A 方案即文档 | B 视频即代码 | C 一键成片 | D 只给标记 |
|---|---|---|---|---|
| B1/B2 能快速核对每个决定 | ✅ 决定清单 + 即时预览 | ⚠️ Studio 能预览，但"决定"散落在代码里 | ❌ 只有结果 | ⚠️ 要进剪辑软件逐个看 |
| B4 局部修改 | ✅ 改一行 | ⚠️ 改代码，非程序员做不了 | ❌ "想救也救不了"（S68） | ✅ 在剪辑软件里改 |
| B3 依据可见 | ✅ 每刀有理由 | ❌ | ❌ 黑盒 | ⚠️ 标记有名字，没有理由 |
| C1/C2 交接剪辑软件 | ✅ 声明式时间线可以确定性导出 | ❌ 官方：无法确定性导出到 OTIO | ❌ | ✅ |
| 阿哲：人和 agent 改同一份东西 | ✅ 同一个 JSON | ⚠️ 双写者问题（Remotion markup skill 第一条规则就在处理这个） | ❌ | ⚠️ |
| 周老师：不用命令行 | ✅ 审阅页 | ❌ | ✅ | ❌ 要会剪辑软件 |
| 小鹿：批量、时效 | ✅ 候选清单 → 批量出片 | ⚠️ 逐帧截图渲染慢（#11911） | ✅ 快，但选得不准（S64） | ❌ 不出片 |
| Kiko：材料，不要成品 | ✅ 材料包 + 导出 | ⚠️ | ❌ "没那味儿" | ✅ |
| F 发布前体检 | ✅ 方案和成片都能检查 | ⚠️ | ⚠️ 分数不透明 | ❌ |
| 长素材精确剪切 | ✅ ffmpeg 流式处理 | ❌ Remotion 自己的 Recorder 也把长录音交给 ffmpeg | ✅ | ✅ |
| 可行性（本机、离线、许可） | ✅ numpy + ffmpeg + 本地 whisper 已验证 | ❌ 约 224MB 下载（计费网络）、macOS 上 Chrome 崩溃（#12680）、≥4 人团队要付费 | ✅ | ✅ |

**选择：以 A 为主干，吸收 D 和 C 的可取之处。**
- 来自 D：导出模式，可以只导出标记、子片段、节拍网格，不剪片（Kiko、阿哲）
- 来自 C：分数只用来**给候选排序**，并且总是和理由一起出现，不替人做决定（F3）

**被放弃的方向和原因**（没有新证据就不要复活）：
- **B 作为核心**：TSX 时间线无法确定性导出到剪辑软件，违背 C1；长素材渲染慢；非程序员没法审阅；还有许可和下载量问题。**保留为将来的可选渲染后端**，只用于合成型内容（知识视频的动效字幕、数据图）：方案 JSON → 固定 composition。等到有证据表明 ffmpeg 的合成能力不够用时再做。字幕交换格式借用 `@remotion/captions` 的 `Caption` 结构（MIT 许可），时间相对源文件。
- **C 作为主路径**：黑盒、改不动，正是亲和图 B3、B4、F4 指出的失败模式。
- **想法 28 留存曲线预测器**：没有任何数据能支撑预测；体检只报告可测量的风险信号，并说明这不是保证。

## 5. 概念模型（Prototype 阶段的起点）

| 对象 | 用户的词 | 说明 |
|---|---|---|
| Source | 素材 | 视频/音频/图片/文稿/弹幕；带音轨信息和预检警告 |
| Analysis | 分析 | 语音、文字稿（逐词）、节拍、镜头切换、响度、弹幕密度；有缓存，可以复用 |
| Plan | 方案 | 声明式时间线：用了哪些素材的哪些片段、按什么顺序、加什么字幕/画面/音乐、输出什么画幅 |
| Decision | 剪 / 留（一刀） | 方案中的一个片段：动作、理由、把握度、证据（文字、电平、弹幕倍数）、是否锁定 |
| Recipe | 配方 | 去停顿、去重说口头禅、游戏实况、直播高光、卡点混剪、鬼畜材料、知识视频 |
| Review | 审阅 | 预览、切换、拖动边界、保护、只看拿不准的 |
| Render / Export | 出片 / 导出工程 | mp4（可多条）、FCPXML、EDL、SRT、标记 |
| Check | 发布前体检 | 开头、死寂、节奏、字幕、响度、画幅 → 风险时间线 + 修改建议 |

**动作**：分析 → 生成方案 → 审阅 → 出片 / 导出 → 体检（体检的结果可以回到方案再改）
**交互类型**：对人是"操作对象"（审阅页里直接切换和拖动）加"下指令"（CLI）；对 agent 是"下指令"（CLI 加 JSON）。
**两条鸿沟**：
- 执行鸿沟：用户的词就是命令名和按钮名（"去停顿""高光""出片"），配方名不用术语
- 评估鸿沟：每个决定都写明理由；方案摘要说清楚"原来多长、剪掉什么、剩多长、几处拿不准"；出片后告诉用户实际结果和校验
