# Personas

证据：亲和图 `../02-define/affinity-diagram.md` 的各簇 · 来源 ID 见 `../01-empathize/traces-raw.md` · 只有需求方陈述支撑的细节标 [R]，假设标 [A] · 日期：2026-10-28
每个 persona 都是**跨来源行为模式的合成体**，不对应任何一个具体的人。名字是化名，配图用中性的插画或库存图，不用真人照片。

## 主 persona — 阿哲：开发者型多面手 UP 主

证据：B1、B2、B3、C1、C2、D1、D2、E1、F1、F2 · 来源模式：S27/S28（录屏作者写了自己的工具，因为"想要更多交互"）、S47/S48（开发者 YouTuber 用脚本剪死寂，重说的 take 仍要手删）、S09/S23（OBS 录屏）、S33（把粗剪导进剪辑软件接着改）、S57（游戏解说要逐句打字幕）、S61（在 VPS 上录直播）、S32（想偷懒把小错误剪掉）+ R1–R5

| | |
|---|---|
| 年龄 / 阶段 | 20–30 岁，学生或刚工作，业余到半职业做视频 [A] |
| 情境 | 晚上或周末剪；同时做讲解视频（编程/游戏攻略）、游戏实况，偶尔切自己直播的高光 [R] |
| 身边的技术 | OBS 多音轨录制、ffmpeg、DaVinci Resolve 或剪映、Claude Code、本地 whisper；写过剪辑脚本 |

**目标**
- 在不降低质量的前提下多更新几条（S48："20 分钟要剪成 10 分钟"）
- 自己决定内容和节奏，把机械活交出去
- 视频能被推起来，也就是需求方说的爆款 [R5]

**动机**
- 表达和分享；视频数据好是持续做下去的动力 [A]

**痛点**（引用数据）
- 重说的 take 和死寂要一刀刀删（E1；S48："我只需要删掉录了两三遍的段落"）
- 自动工具会切到半个字，参数要整条跑完才知道对不对（A2、B2；S08、S14）
- 导进剪辑软件以后音画不同步、轨道不联动、多音轨只剩混音（C2、D2；S15、S18、S55）
- 字幕剪完对不上，只能重做（C3；S39）
- 不知道开头哪里会让人划走（F1、F2）

**行为**
- 不用"全部应用"，每个自动结果都要过一遍（B1）
- 越来越多地让 agent 代劳："帮我把这条剪了"，然后看 agent 的结果和摘要 [R1]
- 最后在 Resolve 里加画面、调色，发布后看留存曲线（F1）

**一句话**："你替我剪可以，但得让我一眼看出你剪了什么、为什么剪，剪错的地方我点一下就能改回来。"

**设计含义**
- 机器的每一个剪辑决定都要能被看到、被说明、被单独撤销；人和 agent 改的是同一份东西
- 不渲染也能预览；改完再出片，或交给 Resolve
- **不做**：上传云端、自动发布到平台、模板商城

## 次要 persona 1 — 小鹿：直播切片作者

证据：E3、A3、F3、F4、G2、H1、C4 · 来源模式：S58（游戏切片评测者逐条审阅、额度不够用）、S59/S60（带货和娱乐切片：授权、多账号矩阵、时效）、S61–S63（录播自动切片的 VPS 用户）、S64–S66（主播"没时间剪"，对 AI 切的结果不满意）

| | |
|---|---|
| 年龄 / 阶段 | 学生、宝妈、待业者、工作室员工（S59） |
| 情境 | 主播下播后的几小时内；一天要处理 2–4 小时的录像，一次出好几条 |
| 身边的技术 | 手机剪辑或剪映；部分人用录播机 + VPS；用过 Opus Clip、Eklipse 这类按积分收费的工具 |

**目标**：赶在热度还在的时候发出有看点的切片；每条都要有开头钩子、竖屏、字幕
**动机**：流量和带货分成；也有人是"为爱发电"的粉丝（S60）
**痛点**
- AI 选的是平淡的讲话，漏掉了"没人说话但很精彩"的操作（A3；S58）
- 切片在一句话没说完的地方开始或结束（A2；S58）
- 按积分收费，长录像和高频直播很快把额度用光（G2；S58）
- 单纯搬运已经没流量了，需要加"自己的理解"（F4；S59）
**行为**：把候选按评分排序，再逐条看（F3；S58、S64）；没有授权不敢发（H1）
**一句话**："给我一个排好序的候选清单，每条告诉我为什么值得切，我挑 5 条就走。"
**设计含义**：候选高光要带理由（弹幕爆发、音量峰、关键词、画面剧烈变化）；切点落在说完话的位置；批量出竖屏和字幕；本地运行、不按积分收费；在输出里提醒授权

## 次要 persona 2 — 周老师：录课的讲师 / 知识作者

证据：A1、A4、C3、D4、B5 · 来源模式：S05（讲课视频要留戏剧性停顿，客户要求"没有死寂"）、S53（教育视频创作者以前靠剪辑师"剪得很差还花几个小时"）、S46（做听力材料要保留最小停顿）、S72（讲解视频节奏太快、代码看不清）、S39（字幕断句和同步）

| | |
|---|---|
| 年龄 / 阶段 | 30–55 岁 [A]，大学讲师或培训师 |
| 情境 | 在不算安静的教室或办公室录课，素材 40–90 分钟 |
| 身边的技术 | 剪映或 Premiere 只会基本操作；**不用命令行**；习惯看文字稿 [A] |

**目标**：去掉卡壳和长停顿，保留讲解的节奏；学生能跟上；配好字幕
**痛点**：教室底噪会让静音检测失效（D4）；自动剪法把讲课的停顿也剪没了（A1）；字幕要手动校时间（C3）
**行为**：在文字稿上审阅比在波形上审阅更顺手（B5）
**一句话**："停顿是给学生想一想的，别都剪了。"
**设计含义**：嘈杂环境下也要能用（自适应判断安静）；默认保留讲解用的停顿；审阅界面以文字稿为主，不需要命令行也能用；字幕默认开启（照顾听障学生）
**无障碍**：这个 persona 代表了依赖字幕的观众，也代表视力下降、不熟悉技术的使用者。审阅界面要有大字号、键盘可操作，并且不能只靠颜色区分"保留"和"剪掉"。

## 次要 persona 3 — Kiko：鬼畜 / 混剪手艺人

证据：E2、B4、C1、F4 · 来源模式：S70（对拍是最费力的部分，想把节拍导出成剪辑软件里的标记）、S78（拼字要 30 小时以上，"为爱发电"，社区说 AI 做的"没那味儿"）、S79–S81（用 Vegas 加 MIDI 脚本对拍，新手卡在安装上）、S68（一键混剪是"黑盒"，"想救也救不了"）
**证据偏薄**：鬼畜的中文来源只有 S78、S82 两个媒体报道，混剪只有 S68 一个第一手来源。这个 persona 需要访谈来验证。

| | |
|---|---|
| 年龄 / 阶段 | 学生为主 [A] |
| 情境 | 一个作品打磨几周到几个月；用 Vegas、Shotcut、FL Studio |
| 身边的技术 | MIDI 和对拍脚本；手动调音 |

**目标**：把创意做出来，并且被同好认可"有那味儿"
**痛点**：拼字、切音节、逐拍对齐这些体力活（E2）；自动工具是黑盒，结果改不动（B4）
**行为**：只接受能接着手改的半成品；不愿意让机器替他做审美决定（F4）
**一句话**："帮我把字切好、拍子标好，怎么排是我的事。"
**设计含义**：提供材料而不是成品：音节切片、节拍网格、第一版对拍（first assembly）、能导出到剪辑软件的标记；每一刀都能单独挪动

## 这组 persona 覆盖了什么、没覆盖什么
- 技术能力：从会写脚本、用 agent（阿哲），到不碰命令行（周老师）
- 动机：数据驱动（小鹿）、表达和教学（周老师）、手艺（Kiko）
- 年龄和能力：包括依赖字幕的观众（周老师的学生），以及视力和操作上的无障碍需求
- **没覆盖**：企业营销团队批量混剪（S68 的 B 端）；多机位访谈播客（证据不足）
- 校验："这会不会就是我们看到的某个人？"每个 persona 都由 3 个以上来源的共同模式拼成；Kiko 的证据最薄，已标注
