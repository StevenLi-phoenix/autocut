# Wireframes（lo-fi）— 审阅页与 CLI 输出

日期：2026-10-28 · 保真度：ASCII 线框（结构、层级、状态），不涉及视觉风格
**这个原型要回答的问题**：
1. 阿哲和周老师能不能在**不渲染**的前提下，几分钟内核对完一份方案，并改掉错的那几刀？（SB1 第 3–4 格，SB4 第 3–4 格）
2. 小鹿能不能从候选清单里挑出 5 条，并且看懂每条入选的理由？（SB2 第 3–4 格）
3. CLI 的摘要能不能让人（和 agent）一眼知道"发生了什么、下一步做什么"？（评估鸿沟）

## 1. 审阅页 — 单条时间线（去停顿、去重说、游戏实况、知识视频）

```
┌───────────────────────────────────────────────────────────────────────────────────┐

```

**结构依据**
- 以文字稿为主栏（B5，S38："还是想以文本字幕为主 panel"），时间线和波形为辅（S27、S38）。
- 每一刀都在原位写明 `动作 · 理由 · 把握度`（B3）；拿不准的标 ⚠ 并给出两个按钮（B1）。
- "按方案播放"直接跳过剪掉的区间，不需要渲染（B2）。播放头同时显示成片时间和原片时间，交接剪辑软件时对得上（C2）。
- 节奏档位改的是保留多长的停顿，改完立即反映在方案里（A4）。
- **无障碍**：剪掉的部分同时用删除线、斜纹、✂ 图标表示，不只靠颜色；全部操作都能用键盘完成；字号跟随系统设置；支持 `prefers-reduced-motion` 和深浅色主题。

**状态**
| 状态 | 显示 |
|---|---|
| 首次打开 | 顶部一行提示："✂ 是建议剪掉的地方。按 ⇧K 只看拿不准的 3 处；满意就点'出片'。"可以关闭，之后不再出现 |
| 部分能力 | 横幅："没检测重说和口头禅：找不到语音识别模型（models/ggml-large-v3-turbo.bin）。现在只剪停顿。"附带说明怎么补上 |
| 素材丢失 | 横幅："找不到素材 talk_zh.mp4（方案里记的路径：…）"＋[重新定位] |
| 方案被外部修改 | 例如 agent 或编辑器同时改了文件：横幅"方案在外部被修改了（3 处）"＋[载入新版本]/[保留我的版本]。不静默覆盖（Remotion markup skill 第一条规则也在处理这个双写者问题） |
| 出片中 | 底部进度条（阶段 + 百分比 + 预计剩余时间），可以取消 |
| 出片完成 | 常驻状态行："成片：talk_zh.cut.mp4 · 21:05 · 音画同步 ✓ · 响度 -14.2 LUFS"＋[在 Finder 中显示] |
| 错误 | 说明发生了什么、为什么、下一步怎么办，例如"ffmpeg 无法读取第 2 条音轨：……可以改用混音轨，或者用 --track 指定" |

**结构依据**：分数只用来排序，理由永远和分数一起显示（F3）。诱饵被列出来并说明为什么没选，而不是被悄悄过滤（B3）。开头和结尾吸附在句子边界上，可以按秒微调（A2）。授权提醒放在出片按钮旁边，在做决定的那一刻出现（H1；ethics："解释放在要紧的时候"）。

## 3. CLI 输出（人在终端里时）

```
$ autocut cut talk_zh.mp4
✓ 素材   talk_zh.mp4 · 38:12 · 1920×1080 · 30fps · 音轨 mix / mic（用 mic 判断）
✓ 分析   语音 · 文字稿（large-v3-turbo，中文）· 41s
✓ 方案   talk_zh.autocut.json
         38:12 → 21:05（剪掉 17:07，45%）
         ✂ 长停顿 23 · 重说 14 · 口头禅 9      ⚠ 拿不准 3
下一步
  autocut review talk_zh.autocut.json   在浏览器里逐条核对（推荐）
  autocut render talk_zh.autocut.json   直接出片
```

- 进度和警告写到 stderr，结果写到 stdout。不是 TTY，或者设置了 `NO_COLOR` 时，不输出颜色和动画（CLI 对 agent 的规范见 ACI 文档）。
- 预检警告（D1）在分析之前出现，并说明会怎么处理："⚠ 可变帧率（录屏常见）：出片时会统一成 30fps，否则音画可能错位。"
