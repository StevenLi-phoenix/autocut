# 认知走查：autocut 审阅页

**证据等级：检查（inspection），不是用户证据。** 评估者站在 persona 的角度，沿每个故事板的**正确路径**逐步提问。结论是"可能卡住的地方"，要靠 `usability-test-plan.md` 的真人测试来确认。
日期：2026-10-28 · 评估对象：审阅页 `src/autocut/review/`，提交 `06faa92` · 评估者：1 名独立评估者 · 截图：`img/hci-*.png`（清单见 `heuristic-evaluation.md` 第 1 节）· 问题编号（H*、A-*）对应 `heuristic-evaluation.md`

每一步回答 4 个问题：

- **Q1 知道要做什么吗？** 用户此刻会不会想去达成这个效果？
- **Q2 注意到这个操作吗？** 正确的操作在界面上看得见吗？
- **Q3 能把操作和目标对上吗？** 看到操作时，会认为它就是自己要的吗？
- **Q4 做完能看出进展吗？** 操作之后，界面给的反馈够不够？

答案用 **是 / 部分 / 否**。任何"否"（以及有实质风险的"部分"）都在表后写原因和改法。

走查用的方案：SB1 和 SB4 同时用演示方案（talk_zh，手写了 2 处拿不准）和真实 `cut` 方案（talk_zh，0 处拿不准），两者的差别会写出来；SB2 用演示和真实的 `highlights` 方案（stream_vod）；SB3 用真实的 `ytpmv` 方案。

前提：agent 已经生成方案并告诉阿哲"去审阅页看看"。阿哲熟悉剪辑软件和快捷键，用鼠标加键盘。

| 2 | 点"▶ 按方案播放"（或按空格）预览 | 是 | 是 | 是 | 是 | 按钮旁写着"播放时跳过剪掉的部分"；跳过时左上角闪出"✂ 跳过 1.5s · 长停顿"，读数同时给成片和原片时间 |

**1-a（第 3 步，真实方案）Q1、Q2 为"否"：没有拿不准，阿哲不知道该先看哪里。**
原因：`cut` 配方的把握度按类别取常数，talk_zh 真实方案里 0 处低于 0.75（`hci-09`），"⚠ n 处拿不准"按钮根本不出现。那个"故意留给观众看代码"的停顿显示为"剪掉 · 95%"。SB1 第 2 格"有 3 处我拿不准，标黄了"这一刻不会发生。
改法：配方的把握度要随证据变化（H1-1）；页面在 0 处拿不准时提示"没有拿不准，不等于都对"，并提供抽查路径，例如每种理由抽 3 处、按停顿长度从长到短看。

**1-b（第 5 步，"拿不准"筛选下）Q4 为"否"：刚确认的那一行消失，焦点也丢了。**
原因：确认后把握度变成 1，筛选立即把它隐藏；焦点回到一个隐藏元素上，于是掉到 `<body>`（`hci-03`）。阿哲看不到自己刚才改成了什么，也没法顺手按 J 去下一处，按 Tab 会从页首重新开始。
改法：确认后在当前视图保留这一行，标"已确认 ✓"，并把选中和焦点移到下一处拿不准（H1-2、A-1）。

**1-c（第 6 步）Q3 为"否"：`[` `]` 是"边界提前/推后"，不是"多留/少留"。**
原因：演示方案把一个 1.9s 的停顿拆成两段："自然停顿 0.40s（保留）"和"长停顿 1.50s（剪掉）"。真实方案只有剪掉的那一段，保留的 0.38s 藏在相邻片段里。要多留，得选中剪掉的那一段，在起点上按 `]`（往后推）；默认微调的是起点，要动终点得先按 E。从"微调边界 50ms"这几个字推不出该按哪个键。拖动剪口可行，但提示只在时间线图例下面一行小字里。Q1 也只是"部分"：阿哲不确定是该先点"保留"再缩短，还是直接拖。
改法：在选中的停顿行上直接放"多留 0.5s / 少留 0.5s"；一个停顿合成一行显示"停顿 1.9s → 留 0.4s"（H2-3、H8-1）。

**1-d（第 9 步）Q2、Q3 为"否"：页面上没有调整顺序的操作。**
原因：体检能指出开头的问题（"第一帧就已经在说话"，或者"前 N 秒没有声音也没有画面变化"），但审阅页只能剪、留、挪边界，不能把后面的一句移到开头或复制到开头。
改法：在行菜单里加"移到开头 / 复制到开头作预告"（方案里片段的先后就是成片的先后）；做不到就在体检建议里写明"这一步在剪辑软件里做"，并直接给出导出入口（H9-1）。

**1-e（第 10 步）Q4 为"部分"：不知道工程里有没有字幕。**
原因：导出菜单把"Final Cut Pro / Resolve"和"字幕 srt"并列，toast 也不说工程里包含什么。
改法：导出完成的提示里列出包含的内容（视频轨、音轨、字幕、标记），或者提供"工程 + 字幕"的组合选项。

**2-a（第 1 步）是信任校准方面的风险，不是可学性的"否"。**
配方按 `n=3` 预选了前 3 名，小鹿可能直接点"出片"。真实方案只有 4 个候选（3 条选中加 1 条诱饵），"挑"的空间很小。可以在测试里观察：她会不会逐条预览，还是直接信任预选？

**2-b（第 2 步）Q2、Q4 为"部分"：点过候选以后，空格和 ↑↓ 都没反应。**
原因：焦点停在候选按钮上，空格被这个按钮吃掉（等于再点一次当前候选），↑↓ 也被放行（H7-1，CDP 实测）。小鹿会以为预览坏了，转而去点播放键。
改法：候选按钮上的空格映射为播放，↑↓ 切换候选。

**2-c（第 6 步）Q3 为"否"：拿不准是关于结尾切点的，按钮却是"保留 / 剪掉"整段高光。**
原因：⚠ 的原因写在"结尾：……只能在电平最低处硬切"里，行内操作却是"保留 / 剪掉"整段高光，而且"保留"已经是按下的样子（`hci-08`）。小鹿很可能把"剪掉"理解成"同意硬切"，结果删掉这条切片的主体。正确做法是"结尾 ±1s，然后试听，再点保留确认"，可这三步之间没有任何提示把它们串起来，调过结尾 ⚠ 也不会消失。
改法：拿不准要带类型；切点类的拿不准给"试听结尾 / 结尾 −1s / +1s / 就这样"，调过边界就算确认（H2-1、H4-4）。

**2-d（第 8 步）全部为"否"：竖屏预览里没有字幕，也没有字幕设置。**
原因：方案里 `captions.burn = true`，但审阅页不显示字幕，也不显示字幕状态（H1-3）。小鹿只能出片以后打开文件看。
改法：9:16 预览叠加烧录效果的字幕，显示"字幕：烧进画面 ✓"。

## SB4：周老师不用命令行，只用审阅页调节奏、删口误、确认字幕

前提：研究者帮他启动了审阅页（测试计划第 47 行）。他不碰终端，习惯看文字稿，可能会用 200% 缩放，或者只用键盘（测试计划第 27 行）。

**4-a（第 2 步）Q2、Q3 为"部分"：看不出哪个停顿是"提问后的停顿"。**
原因：SB4 第 3 格设想工具会标出"保留：讲解停顿"，但真实 `cut` 配方没有这一类，所有长停顿一律"剪掉 · 95%"，理由只写时长（"停顿 1.89s → 保留 0.38s"）。周老师只能靠前后的句子（问句结尾）自己判断。好在文字稿把句子和停顿按顺序排在一起，这一点比波形顺手。
改法：配方识别"问句后的停顿"并默认保留，或者至少把它标成拿不准；理由里写"前一句是提问"。

**4-b（第 3 步）Q3、Q4 为"否"：节奏档位点了不生效，只给一条终端命令，而这条命令在当前版本不存在。**
原因：`hci-04`。横幅让他"在终端运行 `autocut cut … --pace relaxed`"。他不用命令行，而且 06faa92 里没有 `autocut.cli`（H3-1）。档位看起来是可以点的单选，点了却没变化，他可能会反复点。
改法：在页面里直接重算停顿的保留时长，跳过人改过的片段；做到之前，至少把档位改成只读，并告诉他页面内的替代路径（第 4 步）。

**4-c（第 6 步）全部为"否"：页面里没有字幕。**
原因：H1-3。周老师最在意听障学生能不能跟上，可他在出片前完全看不到字幕。导出 srt 之后，还得自己找软件打开。
改法：视频上叠加字幕预览，文字稿行旁边标出字幕断句；提供字幕开关。

**4-d（第 7 步）Q3、Q4 为"部分"：不知道字幕会不会烧进画面。**
原因：`cut` 方案默认 `burn = false`，出片会生成一个单独的 `.srt`，但完成行不提它（`hci-07`）。体检里的说明是"烧录字幕（render 的 burn_captions=True）"，用的是参数名，页面上也没有对应的开关（H9-1、H2-2）。周老师很可能把一个没有字幕的 mp4 发出去。
改法：出片前显示"字幕：烧进画面 / 单独文件"，可以切换；完成行列出字幕文件。

**4-e（键盘或 200%）Q2、Q4 为"否"。**
- 200% 缩放（`hci-10`）：文字稿排在视频和时间线之后，页面纵向 833px 处才开始，而且是一个 270px 高的内滚动区，一屏只能看到 2–3 行（A-2）。
- 只用键盘：在"拿不准"筛选里，每确认一处，焦点就掉到页首（A-1）。另外，从页首 Tab 到文字稿要 25 下，不过有"跳到文字稿"链接可以缩短。
- 改法：见 A-1、A-2。

## SB3：Kiko 做鬼畜的第一版对拍

**审阅页基本覆盖不到 SB3，Kiko 的主路径是"导出工程"**（SB3 第 4 格），所以这里只指出缺口，不逐步走查。

用真实的 `ytpmv` 方案打开审阅页（`hci-11`）时看到的情况：

- 页面进入单条时间线模式，配方标签是"鬼畜材料"。每个音节一行，例如"我 · 音节 · 第 1 小节第 1 拍 ·「我」"；重复的音节写着"（重复，鬼畜点）"。按行看材料是清楚的。
- **没有节拍网格，BGM 也不在预览里**。时间线是原片时间轴，音节按它在台词里的位置排列，而不是按落在哪一拍；播放器只播视频素材的片段，方案里的 BGM（`beds`）不会混进来（`static/` 里没有处理 beds 的代码）。Kiko 在页面里听不出对拍效果。
- **能做的修改和他的目标对不上**：每行只有"剪掉 / 试听 / 锁定"和边界微调，不能把一个音节挪到另一拍，也不能改重复次数或变调。
- **最重要的一条备注被藏起来了**："这是第一版对拍，供在剪辑软件里继续编排……全自动做出来的鬼畜容易'没那味儿'"。它是第 4 条，页面只显示前 3 条（H6-1）。偏偏这一条最能对上 Kiko"不要机器替我做审美决定"的态度。
- 首次提示仍然写"✂ 是建议剪掉的地方"，和鬼畜材料没有关系（H8-2）。
- 导出菜单有"标记（节拍/决定）markers"和"Final Cut Pro / Resolve"、"Premiere Pro"，但没说哪种格式里带音节片段、哪种带节拍标记，Kiko 只能逐个试。

建议：既然 SB3 的主路径是导出，审阅页对鬼畜材料只需做到三件事：

1. 顶部把那条"这是第一版"的备注放在第一位，并给出"导出到剪辑软件接着排"的主按钮。
2. 时间线上画出节拍网格，按方案播放时混入 BGM，让他在导出前能确认对得上拍。
3. 导出菜单为每种格式写明包含什么（音节片段、节拍标记、BGM 轨）。

逐拍编排留在剪辑软件里做，这和 persona"帮我把字切好、拍子标好，怎么排是我的事"一致。测试任务 6 的成功标准本来就落在剪辑软件里，所以这些缺口对任务 6 的影响有限；要观察的是 Kiko 会不会在审阅页上浪费时间。

## 对可用性测试计划的影响

这一节把检查结果回填到 `usability-test-plan.md`：哪些风险要在真人测试里重点观察，哪些问题最好先修，免得真人测试的名额浪费在已知问题上。

### 测试前建议先修的问题（否则任务会因为已知原因直接失败）

| 问题 | 影响的任务 | 不修会怎样 |
|---|---|---|
| 节奏档位只给命令行，命令当前不存在（H3-1） | 任务 2（所有人）、周老师的整条路径 | 所有参与者用档位都会失败，阿哲用终端也会失败；测出来的只是"这个按钮是坏的" |
| 字幕在审阅页不可见（H1-3） | 任务 1、4、5，周老师的 SB4 | "字幕同步"这个价值点测不了；周老师可能交出一个没有字幕的成片 |
| "拿不准"筛选下确认后焦点丢失（A-1） | 只用键盘的参与者的任务 1 | 无障碍名额的数据会被同一个已知 bug 主导 |
| J/K 说明自相矛盾（H4-1） | 任务 1 | 修起来成本极低，不修会在每个看底栏的人身上制造噪声 |

如果来不及修，就在任务卡和成功标准里写明，并且分开记录"因已知问题失败"和"新发现的问题"。

### 必须用真实方案测任务 1

演示方案里的"拿不准"和理由是手写的（`scripts/review_demo.sh:68, 87, 107-115`），用它测信任校准，测到的是手写的结果。真实 `cut` 方案在讲解类素材上通常是 **0 处拿不准**（H1-1）。测试计划已经说优先用参与者自己的素材，这一点要坚持，并在记录表里加两项：

- 每位参与者的方案里有几处拿不准（可能是 0）。如果是 0，成功标准③"标为拿不准的每一处都由参与者做过决定"就自然满足，没有意义；要改为观察**参与者主动抽查了多少处 95% 的剪口，怎么选的**。
- 参与者有没有把"95%"当成"不用看"。用测试后的逐句核对，比较"有把握"和"拿不准"两类里的误剪比例。

### 按任务列出要重点观察的风险

| 任务 | 重点观察 | 对应问题 |
|---|---|---|
| 1 去重说 | 用"拿不准"筛选还是 ⇧J；确认后行消失时的反应；会不会去查理由 chip；多少人用了 `[ ]` 或拖动，按错方向几次 | H1-1、H1-2、H2-3、H4-2 |
| 2 调节奏 | 点档位后的反应（反复点？去找终端？放弃？）；能不能自己找到"长停顿 chip → 逐条改回保留"这条路，花了多久、改了几处；想要的是"整体放慢"还是"只留提问后的停顿" | H3-1、H7-2、4-a |
| 3 体检 | 看到建议以后想动手做什么、在哪里找按钮；全片问题标在 00:00 会不会被误读成"开头有问题"；有没有人想调整句子顺序 | H9-1、H1-7、1-d |
| 4 交接 | 导出时会不会另外导 srt；用剪映的参与者能不能找到合适的格式；工程里字幕在不在 | H2-4、1-e |
| 5 小鹿 | 点候选后按空格或 ↓ 的次数和反应；遇到 #3 的"拿不准"时点了什么，有没有误点"剪掉"；会不会注意到预览里没有字幕；是逐条看完，还是直接信任预选 | H7-1、H2-1、2-d、2-a |
| 6 Kiko | 有没有在审阅页上花时间、想做什么；有没有看到（或问起）"这是第一版"那条备注；在剪辑软件里找不找得到节拍标记 | SB3 一节、H6-1 |
| 7 agent 双写 | **关键任务。** 事先安排 agent 做 2–3 处改动，其中一处剪掉整句。观察：页面没有未保存改动时自动载入，参与者能不能发现 agent 改了什么、改在哪里；出现冲突横幅时选了哪个、知不知道会丢掉什么、冲突期间是否继续编辑。按测试计划的规则，agent 剪掉了句子而参与者没发现，记为严重度 4 | H1-4、H3-2 |
| 周老师（200% 或只用键盘） | 能不能找到文字稿（它在视频和时间线之后）；在 270px 的内滚动区里要滚多少次；会不会用 Aa；只用键盘时焦点丢失的次数 | A-1、A-2、A-3 |

### 建议加进记录表的指标

- 点节奏档位的次数，以及之后做了什么
- 确认后行消失的次数，以及立即撤销的次数
- 主动抽查的高把握度剪口的数量（研究问题 2）
- 对体检建议，"想做但找不到入口"的次数（研究问题 6）
- 外部改动从发生到被参与者发现的时间，以及是否被发现（研究问题 5）
- 出片后有没有发现字幕没烧进画面

### 结论：是否可以拿去做真人测试

**核心审阅循环可以测**：看懂一刀、改掉、撤销、保存、出片、导出，都能用，反馈充分，SB1 的大部分步骤和 SB2 的挑选、调整、出片都能走通。**但按现在的版本直接测，任务 2、周老师的整条路径和无障碍名额的结果会被已知问题主导**。建议先修上面"测试前建议先修"表里的 4 项（其中节奏档位和字幕是功能缺口，工作量最大），并让任务 1 和任务 7 用真实方案和事先安排好的 agent 改动。修完以后，可以进入第 1 轮 5 人测试。
