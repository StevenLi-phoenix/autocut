**证据等级：检查（inspection），不是用户证据。** 这里的发现来自评估者对界面和代码的检查，没有真实用户参与，只能说明"这里很可能出问题"，不能说明"用户在这里出了问题"。要确认，需要做 `usability-test-plan.md` 里的真人测试。

## 1. 怎么检查的

- **实物**：用无头 Chrome 156（独立的临时 profile）打开审阅页，通过 CDP 脚本驱动点击、按键、模拟深色模式、`prefers-reduced-motion`、200% 缩放，并读取页面状态（焦点、可见行、横幅文字、计算后的字号）。
- **方案来源**：
  - 演示方案：`scripts/review_demo.sh`（talk_zh，单条时间线）和 `scripts/review_demo.sh highlights`（stream_vod，候选清单）。分数、理由和"拿不准"都是手写的。
  - 真实方案：在 `fixtures/media/` 上直接调用配方：`cut.build` 处理 talk_zh、lecture_en、game_commentary，`highlights.build` 处理 stream_vod（带弹幕），`ytpmv.build` 处理 ytpmv 素材。
  - 构造的异常状态：素材路径失效；没有文字稿（模拟没装语音识别模型）；页面有未保存改动时，方案文件被外部改写（模拟 agent 双写）。
- **走过的功能**：体检、导出 fcpxml、出片（含"还有拿不准"确认框、进度、完成）、撤销/重做、理由筛选、节奏档位、裁切框、开头/结尾微调、Aa 字号。
- **局限**：只有 1 名评估者（方法建议 3–5 名，所以会漏掉一些问题）；没有用 VoiceOver 实测，读屏只检查了 ARIA 标注和播报文字；素材是合成的测试卡，真实素材上的理由文案和把握度分布可能不同。

## 2. 总体印象

审阅的基本循环已经能用：看懂一刀为什么剪，改掉它，撤销，自动保存，出片，导出。"修订模式"这个隐喻落实得好：剪掉的句子有删除线、斜纹条、✂ 标签和"剪掉"文字，四重编码；每一刀都写了理由和把握度；出片前如果还有拿不准，会弹确认框；多数错误信息说清了原因和下一步。

主要问题集中在三处：

1. **审阅之后的动作要回到命令行，或者根本没有入口**：调节奏、看字幕、按体检建议改，都做不了。
2. **"拿不准"这条主线在真实方案上几乎不出现。**
3. **人和 agent 共用一份方案时，人看不出 agent 改了什么，冲突时只能整份二选一。**

另外还有几个键盘和缩放下的断点，会直接影响周老师那一类参与者。

## 3. 按 Nielsen 10 条逐条检查

每条先写做得好的地方，再列问题。问题编号 `H<条目>-<序号>`；`A-` 开头的是无障碍问题，放在第 4 节。

### H1 系统状态可见

做得好：顶栏同时显示"原片 → 成片 · 剪掉多少（百分比）"和"⚠ n 处拿不准"；保存状态常驻（"✓ 已保存 · 改动 1 处"）；按方案播放跳过剪掉的部分时，左上角会闪出"✂ 跳过 1.5s · 长停顿"；读数同时给成片时间和原片时间；出片有阶段、百分比、预计剩余时间和取消按钮。

**H1-1 真实方案里几乎没有"拿不准"，分诊信号是空的** · 严重度 **3**
- 位置：配方给的把握度（`src/autocut/recipes/cut.py:427, 491, 727, 774, 800, 833, 848`）× 页面阈值 `UNCERTAIN_BELOW = 0.75`（`static/model.js:5`）；截图 `hci-09`。
- 现象：`cut` 配方的把握度按类别取常数：说话 0.95、停顿保留 0.9、长停顿 0.95/0.85、重说 0.95/0.85、口头禅 0.9/0.8。只有游戏实况里"无解说"的一部分会低于 0.75。talk_zh 和 lecture_en 的真实方案都是 **0 处拿不准**。game_commentary 里"人声停顿但游戏有动静"那段的把握度正好是 0.75，没被标成拿不准。演示方案里那 2 处拿不准是手写的（`scripts/review_demo.sh:68, 87`）。比如 31–34 秒那个"可能是故意留给观众看代码"的停顿，在真实方案里是"剪掉 · 95%"。
- 为什么是问题：设计假设机器能告诉人"该看哪里"（SB1 第 2 格"有 3 处我拿不准，标黄了"）。把握度不随证据变化时，整页都显示 95%，用户只剩两种选择：全部重看（审阅省不了时间），或者全部相信（误剪的地方漏掉）。这直接打在研究问题 2"信任校准"上。
- 建议：配方的把握度要跟着证据变（停顿前后是否在讲代码或刚问完问题、重说的相似度离阈值有多近、口头禅前后的停顿长度）。页面在 0 处拿不准时不要沉默，改为提示"没有拿不准的地方，不等于都对"，并提供抽查导航，比如按理由各抽 3 处、优先看最长的停顿。

**H1-2 在"拿不准"筛选下确认一处，那一行直接消失** · 严重度 **3**（无障碍部分见 A-1）
- 位置：`static/transcript.js:130-139`（筛选按 `isUncertain` 重新计算）+ `static/model.js:232-240`（确认后把握度改成 1）+ `static/app.js:435`（把焦点交还给这一行，但它已经隐藏了）；截图 `hci-03`。
- 现象：点"保留"或按 X 后，这处不再算拿不准，于是被筛选掉。屏幕上只剩下一处，没有"已确认"的反馈。CDP 实测焦点落到了 `<body>`，下一个 Tab 会从页首的"跳到文字稿"重新开始。
- 为什么是问题："只看拿不准"是最自然的核对方式，结果每做一个决定，刚改的那一处就从眼前消失：用户既看不到改成了什么，也没法立刻撤销确认。键盘用户还会丢掉自己的位置。
- 建议：确认后让这一行在当前筛选里留到用户离开（加"已确认 ✓"标记，变淡），并把焦点和选中移到下一处拿不准；筛选按钮上显示"拿不准 1/2 已处理"。

**H1-3 字幕在审阅页里完全不可见** · 严重度 **3**
- 位置：`static/` 下没有任何字幕显示或设置（全文搜索 caption 和"字幕"，只有导出菜单里的 `srt`，`static/app.js:23`）；方案里有 `captions.enabled / burn`；出片会在成片旁边多写一个 `talk_zh.main.srt`，完成行不提这个文件（`hci-07`）。
- 为什么是问题：SB4 第 4 格"字幕已经同步好了"、SB2"每条都要有字幕"、周老师的设计含义"字幕默认开启（照顾听障学生）"，都需要在出片前看到字幕。现在只能出片或导出 srt 之后到别处去看。剪辑和字幕的同步（C3）是这个产品的卖点之一，却没有地方能确认。
- 建议：预览上叠加字幕（按 `captions.burn` 决定是否显示为"烧录"效果）；顶栏或出片按钮旁显示"字幕：烧进画面 / 单独 srt / 关"并可切换；完成行列出字幕文件。

**H1-4 看不出 agent 在外部改了什么；自动载入还会清空撤销历史** · 严重度 **3**（如果 agent 的改动包含剪掉整句，按测试计划的规则会升为 4）
- 位置：`static/app.js:591-603`（页面没有未保存改动时，外部修改直接载入，只弹 5 秒 toast"方案在外部被修改了（n 处），已载入新版本"）、`static/app.js:580`（`state.undo.clear()`）。
- 为什么是问题：研究问题 5 和测试任务 7 要的是"人在审阅页能看出 agent 改了什么"。现在只给一个数字，改动的行没有标记，原来的撤销历史也没了。agent 如果多剪了一句，用户很可能在 toast 消失后完全没察觉。
- 建议：载入后把改动的行标成"agent 改过"（类似修订模式里另一位作者的颜色和标签），给一个"外部改动 n 处"筛选和逐处跳转；撤销栈保留，外部改动作为一条可撤销的记录。

**H1-5 改过以后，理由文字还是机器原来的说法** · 严重度 2
- 位置：`static/transcript.js:220`（一律显示 `seg.detail`）、`static/app.js:829-830`（候选的"开头/结尾"说明直接用 detail）；截图 `hci-05`、`hci-08`。
- 现象：长停顿改回整段保留以后，还写着"停顿 1.89s → 保留 0.38s · 已改"；候选开头往前多留 1 秒后，行里是"铺垫 6.00s"，右栏仍是"开头：铺垫 5.0s"。
- 建议：编辑之后把机器说明降为次要的"机器原判：…"，主文案显示当前的实际值。

**H1-6 出片完成行少了响度、字幕文件和完整路径** · 严重度 2
- 位置：`static/app.js:1059-1074`；截图 `hci-07`。实际显示"成片：talk_zh.main.mp4 · 00:28 · 音画同步 ✓"，完整路径只在鼠标悬停的提示里。线框承诺了"响度 -14.2 LUFS"。
- 建议：显示响度（如果出片时没做标准化，就写"未标准化"）、字幕文件和输出目录；"在 Finder 中显示"保留。

**H1-7 体检里针对整条视频的问题被画成 00:00 的点** · 严重度 2
- 位置：`check.check()` 对全片问题返回 `at=0, end=时长`（响度、分辨率、字幕都是这样）；`static/app.js:1131-1146` 把它们画在风险时间线的 0 点上，列表里也写"00:00"；截图 `hci-06`（三个 ◆ 叠在开头）。
- 建议：覆盖全片的项单独放在"全片"一组，不上时间轴，时间列写"全片"。

### H2 系统与现实世界匹配

做得好：用的是创作者的语言（重说、口头禅、长停顿、铺垫、高光）；候选清单的理由很具体（"弹幕 18.4× 爆发（峰值 4.6 条/秒）"、"89% 是同一句「1」，判为抽奖刷屏，没选"）；候选的 ±1s 按钮下面专门写了"−1s 是往前多留 1 秒"。

**H2-1 候选清单里的"拿不准"，给出的操作对不上问题** · 严重度 **3**
- 位置：`static/transcript.js:232-236`（拿不准的行一律给"保留 / 剪掉"两个按钮）；演示方案 #3（`scripts/review_demo.sh:111-112, 123`）、真实方案 clip_4（高光段把握度 0.6）；截图 `hci-08`。
- 现象：#3 拿不准的原因写在"结尾"说明里："这里一直有人说话，找不到不打断句子的位置，只能在电平最低处硬切"。页面给的却是"保留 / 剪掉"**整段高光**。点"剪掉"会把这条切片的主体删掉，只剩 5 秒铺垫。真正该做的是"结尾 ±1s，然后试听"，可是做完这一步，⚠ 并不会消失。
- 为什么是问题：小鹿会把"剪掉"理解成"同意这样剪"。按钮的意思和她的目标对不上，误点就会毁掉一条切片。
- 建议：拿不准要带上类型。如果是切点拿不准，就把操作换成"试听结尾 / 结尾 ±1s / 就这样"，并且调过边界就算确认。只有动作本身拿不准时，才给"保留 / 剪掉"。

**H2-2 技术术语直接出现在理由和建议里** · 严重度 2
- 例子：game_commentary 的理由"音轨 2（game）平稳（最多比中位数高 0 dB），画面没有切换"；体检"整合响度 -18.7 LUFS……loudnorm 到 -14 LUFS"、"render 的 burn_captions=True"（`src/autocut/check.py:616, 636`）；出片失败"sources.talk_zh.path='…'"（`hci-12`）。
- 为什么是问题：阿哲看得懂；周老师和小鹿未必。`burn_captions=True` 是给程序员看的参数名。
- 建议：主文案只说结论（"游戏声音也很安静，画面没变"、"音量偏小"），数字和参数放进可展开的"细节"。

**H2-3 `[` `]` 是"把边界提前/推后"，不是"多留/少留"** · 严重度 2
- 位置：`static/index.html:224`、`static/app.js:445-459`；默认微调的是起点，用 E 切换。
- 现象：想让一处剪掉的长停顿多留一点，就要选中那一刀，按 `]`，把剪口的起点往后推。这和"多留"的直觉相反。单条时间线里也没有候选清单那样的一行解释。
- 建议：按"多留 / 少留"来命名和映射（对剪掉的片段，`]` = 少剪），或者在选中行上直接放"多留 0.5s / 少留 0.5s"。

**H2-4 导出菜单里没有剪映** · 严重度 2
- 位置：`static/app.js:21-24`。菜单有"Final Cut Pro / Resolve、Premiere Pro、剪切列表 edl、字幕 srt、标记"；persona 写明阿哲用"Resolve 或剪映"，周老师用"剪映或 Premiere"。
- 建议：如果剪映能导入其中某种格式，就在菜单里写明"剪映（专业版）：用 xxx"；如果不能，就明确标注，免得用户逐个去试。

**H2-5 每一行都有"锁定"，但目前没有任何东西会照它办** · 严重度 2
- 位置：`static/transcript.js:242`（"锁定：重新生成方案时保持不变"）；`cut.build` 只接受 `protect` 区间，不读取旧方案里的锁定片段（`src/autocut/recipes/cut.py:92-110`）；页面上也没有重新生成的入口。
- 为什么是问题：用户锁定了，以为得到了保护，其实没有（参见 H3-1）。对不需要它的人，这又是每行多出来的一个按钮。
- 建议：在重新生成真的会保留锁定片段之前，先隐藏"锁定"；做好之后，再在节奏或重新生成的流程里讲清楚它的作用。

**H2-6 "为什么入选"这个标题也出现在没选的诱饵上** · 严重度 1
- 位置：`static/app.js:827`。抽奖刷屏那条也显示"为什么入选"。没选的候选改成"为什么没选"。

（鬼畜材料在审阅页里的呈现见 `cognitive-walkthrough.md` 的 SB3 一节，评为 2。）

### H3 用户控制与自由

做得好：撤销和重做（⌘Z、⇧⌘Z、⌘Y）覆盖了动作、边界、勾选、裁切框；撤销会自动切回对应的候选；自动保存 800ms；出片可以取消；首次提示和横幅都能关。

**H3-1 节奏档位看起来能点，点了只给一条终端命令，而这条命令现在跑不起来** · 严重度 **3**
- 位置：`static/app.js:1194-1200, 1232-1241`；截图 `hci-04`。`pyproject.toml:10` 把 `autocut` 指向 `autocut.cli:main`，但提交 06faa92 里没有 `src/autocut/cli.py`，`.venv/bin/autocut --help` 直接报 `ModuleNotFoundError: No module named 'autocut.cli'`。
- 现象：点"从容"，档位不变，横幅说"改节奏要重新生成方案……在终端运行：`autocut cut "/Users/…/talk_zh.mp4" --pace relaxed`。已经手动改过、并且锁定（L）的片段会保留"。
- 为什么是问题：
  1. 线框承诺"改完立即反映在方案里"；SB4 的周老师不用命令行，这条路对他是死路。
  2. 这条命令在当前版本根本不存在。
  3. "锁定的片段会保留"没有实现依据（H2-5）。如果以后 CLI 落地时不合并旧方案，按横幅重跑会把人所有的手改覆盖掉，那就是严重度 4。
- 建议：节奏在页面里重算。保留多长的停顿，只需要在已有的停顿片段上重新划分保留和剪掉，不必重新识别语音，人改过的片段跳过。做不到之前，先把档位改成只读显示，并给出页面内的替代做法（理由筛选"长停顿"→ 逐条处理）。

**H3-2 冲突只能整份二选一；冲突期间继续做的修改会一起丢掉** · 严重度 **3**
- 位置：`static/app.js:547-575`（横幅只有"载入新版本 / 保留我的版本"）、`static/app.js:510`（冲突期间 `save()` 直接返回，但页面仍然允许继续编辑）；截图 `hci-05`。
- 现象：横幅只告诉你"（1 处）"，不说是哪一处。冲突出现后，CDP 实测还能继续按 J、X 改，改动在内存里越积越多。点"载入新版本"，这些改动全部丢弃（toast："你没保存的改动被丢弃了"）；点"保留我的版本"，agent 的改动被静默覆盖。
- 为什么是问题：阿哲和 agent 同时改方案正是设计目标（R1、SB1、测试任务 7）。二选一会迫使他丢掉一方的工作，而且他是在看不到差异的情况下做选择的。
- 建议：
  1. 冲突时冻结编辑，或者至少醒目地提示"这之后的改动会参与合并"。

### H7 灵活性和使用效率

做得好：快捷键齐全（空格、J/K、⇧J/⇧K、X、L、[ ]、E、Enter 试听、←→、P）；理由筛选；时间线缩放和拖动边界；"预览所选"可以连续播放所有选中的候选；试听时可以自动播放剪口附近。

**H7-3 边界微调的步长是 50ms，要多留 1 秒得按 20 下** · 严重度 1（⇧ 时是 500ms，也可以拖动，所以影响不大；帮助里写了，底栏没写 ⇧。）

### H9 帮助用户识别、诊断错误并从错误中恢复

**H9-1 体检的建议在页面里没法执行** · 严重度 **3**
- 位置：`hci-06`；建议文字来自 `src/autocut/check.py:616, 636`；出片流程 `static/app.js:986-1012` 没有任何选项。

- 为什么是问题：研究问题 6 问的是"体检的提示是否具体到可以据此动手修改"。现在的提示够具体，但手边没有工具可用。

**H9-2 几条恢复路径都要用命令行** · 严重度 2

- 周老师不用命令行，这些对他都是死路。
- 建议：重新定位时，服务器在常见目录里按文件名和大小找候选并列出来；没有文字稿时，页面上给"开始识别"按钮（后台任务，带进度）。

**A-1 键盘用户确认拿不准后，焦点丢失** · 严重度 **3**
- 和 H1-2 同一个根因。CDP 实测：在"拿不准"筛选下点"保留"以后，`document.activeElement` 是 `<body>`。键盘用户（测试计划要求周老师名额里至少有 1 人只用键盘）每确认一处，都要重新找回位置。违反 WCAG 2.4.3（焦点顺序）。

**A-2 200% 缩放下，文字稿被挤到视频和时间线后面，而且只有 270px 高的内滚动区** · 严重度 **3**
- 位置：`static/style.css:414-424`（窄屏改为单列，`.doc-scroll { max-height: 60vh }`）；截图 `hci-10`。在 1440×900 屏幕上放大到 200%（CSS 视口 720×450）：第一行文字稿在页面纵向 833px 处，差不多要往下翻两屏；进入以后，文字稿在一个 270px 高的嵌套滚动区里，一屏只能看到 2–3 行。没有横向溢出（scrollWidth = 720），这一点做得对。
- 为什么是问题：设计说文字稿是主栏（B5，周老师"在文字稿上审阅比在波形上审阅更顺手"），测试计划也要求有参与者用 200% 缩放。这时主栏退到了最次要的位置。
- 建议：窄屏下把文字稿放到第一位，视频缩成顶部的小窗（可以固定）；去掉嵌套滚动，让文字稿随页面滚动；时间线可以折叠。

**A-3 关键说明的字号偏小** · 严重度 2
- 默认情况下，"✂ 剪掉 · 口头禅 · 71% · 理由"这一行是 13px（`static/style.css:311`），底栏是 12.5px（`static/style.css:390`），而决定本身就靠这一行。Aa 最大也只到 125%（说明行 16.25px）。persona 里的周老师"视力下降"。
- 建议：说明行至少 14–15px；Aa 再加一档 150%，并且在窄屏下重新排版。

**A-4 读屏标签里的时间范围没有信息量** · 严重度 1（`static/transcript.js:190-194`，短片段会读成"00:15 到 00:15"；建议改读起点和时长。）
